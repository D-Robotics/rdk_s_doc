# deb Package Development

The RDK system is based on Debian/Ubuntu, and system components are distributed as deb packages. This section targets Mode 3 (deep customization) users and describes how to develop system components at the deb/source level. For image-level apt/configuration customization, see [System customization](../02_system_customization/01_system_customization.md).

## deb Package Structure

Each `hobot-*` directory under the RDK source `source/` is the source of one deb package. Unlike standard Debian packaging (handwritten `debian/control`, `debian/rules` + `dpkg-buildpackage`), RDK uses a "pre-placed file tree + dynamically generated control by `mk_debs.sh`" approach. The directory structure is as follows:

```
hobot-xxx/
├── debian/           # Packaging content root (the file tree is installed into the rootfs)
│   ├── usr/          # Files installed under /usr (bin, lib, include, etc.)
│   ├── lib/          # Files installed under /lib (used by some packages)
│   └── DEBIAN/       # Optional, pre-placed control / postinst, etc.
└── ...               # Package content sources (source code, configs, firmware, etc.)
```

The `debian/control` is dynamically generated by the `gen_contrl_file()` function of `mk_debs.sh` based on package name, version, and dependencies; no manual writing is needed. The install paths are determined by the file tree location under `debian/`.

## Development Workflow

1. Create a new `hobot-xxx/` directory under `source/`
2. Organize the file tree under `debian/` according to the target install paths (corresponding to `/usr`, `/lib`, etc.)
3. Add the build case for this package in `mk_debs.sh` (copy files, generate control and dependencies)
4. Build: `./mk_debs.sh hobot-xxx` (internally uses `fakeroot dpkg -b` to package)
5. Output goes to `out/product/deb_packages/hobot-xxx_<version>_arm64.deb`
6. Install on the board: `dpkg -i hobot-xxx_*.deb`

## Existing deb Packages

The following are the official deb packages currently supported by `mk_debs.sh` (corresponding to the `hobot-*` directories under `source/`):

| Package | Description |
| --- | --- |
| `hobot-configs` | System config files, boot config and services |
| `hobot-utils` | System utilities (hobot-log, etc.) |
| `hobot-wifi` | Wi-Fi scripts |
| `hobot-io` | I/O library |
| `hobot-io-samples` | I/O library example code |
| `hobot-multimedia` | Multimedia library |
| `hobot-multimedia-dev` | Multimedia development tools |
| `hobot-multimedia-samples` | Multimedia examples |
| `hobot-camera` | Camera/sensor driver |
| `hobot-dnn` | Deep learning inference framework |
| `hobot-spdev` | Multimedia + inference framework |
| `hobot-sp-samples` | Multimedia + inference framework example code |
| `hobot-miniboot` | miniboot upgrade package |
| `hobot-audio-config` | Audio services |
| `hobot-firmware` | Peripheral firmware (Ethernet/USB, etc.) |
| `hobot-ethercat` | EtherCAT support |

For the full list and source directory descriptions, see [BSP source directory structure](../../06_environment_build/02_bsp_source_layout.md).
