# Geometric Distortion Correction - GDC

> **Level description**: This chapter covers the low-level multimedia API (on-board `hb_gdc_cfg.h / hbn_vpf_interface.h`), GDC geometric distortion correction implemented through configuration structs without a standalone function API. It is intended for advanced developers who need to directly operate the multimedia pipeline (Mode 3). If you only need the encapsulated capture/codec/display functionality, see Chapter 4 [Simple API](/Simple_API/multimedia_api/cdev/vio_api) (Mode 1).

> **Platform codename note**: Compatibility annotations in this document follow the original wording of the underlying header files. XJ3/J3 and Ultra are earlier-generation upstream platform codenames; X5 denotes the current upstream product line (not these two boards); Super/J6 are the codenames of the architecture family shared by this product line (board-verified: S100/S600 share the same family, with S600 in a multi-core form). An `HW:` list indicates the interface's applicable range across upstream platform generations, where the Super generation corresponds to this product line (inherited from upstream annotations, not verified per-interface on board); `SW` is the upstream software version number — for RDK releases see the Release Notes. Interfaces without codenames are inherited from upstream and not individually verified on RDK.

## Overview

GDC (Geometric Distortion Correction) is used for geometric distortion correction and stitching of camera images. GDC has no standalone function API; it describes the input/output geometry through configuration structs (the `gdc_config_t`/`gdc_settings_t` in the on-board `hb_gdc_cfg.h`). The configuration binary is generated by `hbn_gen_gdc_cfg` (see 5.5.1.6 VPF/PYM) and set through the GDC channel of an HBN vnode (`hbn_vnode_set_ochn_attr`).

:::info Note

The GDC module takes the output of VPF/PYM as input and outputs to the downstream processing (VENC/VOT, etc.). Its distortion parameters (the mesh mapping table) are generated by `hbn_gen_gdc_cfg` based on the input/output geometry and the distortion model; you do not hand-write the binary.
:::

## Software Abstraction

- `gdc_config_t`: Single-path GDC configuration — input/output width and height, stride, plane count, split mode (`div_width`/`div_height`), `sequential_mode`, etc.
- `gdc_settings_t`: GDC settings — `gdc_config_t` array + the ion share id (`binary_ion_id`) and physical address offset (`binary_offset`) of the configuration binary.
- The configuration binary is generated by `hbn_gen_gdc_cfg` (`hbn_vpf_interface.h`) based on `param_t`/`window_t`, and released by `hbn_free_gdc_cfg`.

## Configuration Item Description

| Struct | Key Field | Description |
|---|---|---|
| `gdc_config_t` | input/output width and height, stride, plane count | Describes the input/output geometry of a single GDC path |
| `gdc_config_t` | `div_width` / `div_height` | Split mode, controls GDC image splitting |
| `gdc_config_t` | `sequential_mode` | Sequential processing mode switch |
| `gdc_settings_t` | `gdc_config_t` array | Multi-path GDC configuration set |
| `gdc_settings_t` | `binary_ion_id` | ion share id of the configuration binary |
| `gdc_settings_t` | `binary_offset` | Physical address offset of the configuration binary |

## API Call Flow

1. Prepare `gdc_config_t`/`gdc_settings_t` (input/output geometry parameters).
2. `hbn_gen_gdc_cfg` generates the configuration binary (see 5.5.1.6 VPF/PYM).
3. Open the GDC module through an HBN vnode, and set the configuration via `hbn_vnode_set_ochn_attr`.
4. `hbn_vnode_start` starts it, output frames are obtained via `hbn_vnode_getframe`; release the binary via `hbn_free_gdc_cfg` when done.

## Quick Example

GDC has no standalone function API; it is used through the "generate configuration binary → set via HBN vnode" configuration flow. The minimal flow to generate the configuration binary is as follows (referencing the on-board `/app/multimedia_samples/sample_gdc/2-generate_bin/`):

```c
#include "gdc_cfg.h"
#include "gdc_bin_cfg.h"

// 1. Parse the JSON configuration (input/output geometry, distortion mapping, etc.)
gdc_bin_custom_config_t cfg = {0};
parse_json_config("./gdc_bin_custom_config.json", &cfg);

// 2. Generate the GDC configuration binary and write it to a file
//    (the same implementation as the on-board hbn_gen_gdc_cfg)
uint32_t *cfg_buf = NULL;
uint64_t config_size = 0;
gdc_cfg_bin_gen(json_str, NULL, (void **)&cfg_buf, &config_size);
save_to_file("./gdc.bin", cfg_buf, config_size);

// 3. Release the generated buffer
hbn_free_gdc_cfg(cfg_buf);
```

When setting it into the pipeline, fill the binary's ion share id and physical offset into `gdc_settings_t` (`binary_ion_id`/`binary_offset`), and set it into the GDC vnode via `hbn_vnode_set_ochn_attr`:

```c
hbn_vnode_handle_t gdc_fd;
hbn_vnode_open(HB_GDC, 0, AUTO_ALLOC_ID, &gdc_fd);

gdc_settings_t gdc_settings = {0};
gdc_settings.binary_ion_id  = cfg_buf_share_id;   /* ion share id of the configuration binary */
gdc_settings.binary_offset  = cfg_buf_offset;     /* physical address offset */
hbn_vnode_set_ochn_attr(gdc_fd, 0, &gdc_settings);

hbn_vnode_start(gdc_fd);
/* get frames via hbn_vnode_getframe ... */
```

## FAQ

### How is the GDC configuration binary generated?

The configuration binary is generated by the on-board `hbn_gen_gdc_cfg` (`hbn_vpf_interface.h`) based on the input/output geometry parameters and the distortion model. After use, it must be released via `hbn_free_gdc_cfg` to avoid memory leaks.

### How is GDC integrated into a pipeline without a standalone function API?

GDC does not provide a standalone function interface. It carries the binary's ion share id and physical address offset through the `gdc_settings_t` struct, which is set into the GDC channel via the HBN vnode's `hbn_vnode_set_ochn_attr`, and then started with `hbn_vnode_start`.
