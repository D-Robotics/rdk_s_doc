## RDK S100
### Temperature Sensors
The RDK S100 chip has 5 temperature sensors, used to display the temperatures of the MCU domain / BPU / MAIN domain. The MAIN domain and the MCU each have two temperature sensors, and the BPU has one temperature sensor.

Under /sys/class/hwmon/, the hwmon0 directory contains the relevant parameters of the temperature sensors:
- temp1_input is the first temperature sensor of the MAIN domain, and temp2_input is the second temperature sensor of the MAIN domain;
- temp3_input is the first temperature sensor of the MCU domain, and temp4_input is the second temperature sensor of the MCU domain;
- temp5_input is the BPU temperature sensor.

The temperature precision is 0.001 degrees Celsius.

```
root@ubuntu:~# cat /sys/class/hwmon/hwmon0/temp1_input
46837
root@ubuntu:~#
```
### Thermal Mechanism
Linux Thermal is the module related to temperature control under the Linux system. It is mainly used to control the heat generated by the chip during system operation, keeping the chip temperature and the device enclosure temperature within a safe and comfortable range.

To achieve reasonable device temperature control, we need to understand the following three modules:

  - Devices for reading temperatures: abstracted as Thermal Zone Devices in the Thermal framework. The RDK S100 has 5 thermal zones, namely thermal_zone0~thermal_zone4, each bound to one of the 5 temperature sensors;
  - Devices for cooling down: abstracted as Thermal Cooling Devices in the Thermal framework, including CPU, BPU, and fan;
    - Devices such as CPU/BPU cool down by adjusting frequency;
    - The fan can cool down by controlling its speed;
  - Temperature control policies: abstracted as Thermal Governors in the Thermal framework;

The information and control of the above modules can all be accessed under the `/sys/class/thermal` directory.

#### Thermal Zone Overview
To get the information of a certain thermal_zone, taking thermal_zone0 as an example, the sample command is as follows:
```shell
root@ubuntu:~# cat /sys/class/thermal/thermal_zone0/type
pvt_cmn_pvtc1_t1
```

To get the current policy of a certain thermal_zone, taking thermal_zone0 as an example, the sample command is as follows:
```shell
root@ubuntu:~# cat /sys/class/thermal/thermal_zone0/policy
step_wise
```

To get the policies supported by a certain thermal_zone, taking thermal_zone0 as an example, the sample command is as follows:
```shell
root@ubuntu:~# cat /sys/class/thermal/thermal_zone0/available_policies
user_space step_wise
```
As you can see, the policies supported by thermal are: `user_space` and `step_wise`
- `user_space`: reports information such as the current temperature of the thermal zone and the thermal control trip points to user space via uevent, and the user-space software formulates the thermal control policy.

- `step_wise`: raises the cooling state step by step in each polling period. It is a relatively gentle thermal control policy.

Which policy to choose is up to the customer based on the product. It can be specified at compile time or switched dynamically through sysfs.
For example: dynamically switch the policy of thermal_zone0 to `user_space` mode
```shell
echo user_space > /sys/class/thermal/thermal_zone0/policy
```

##### thermal_zone0 Overview
thermal_zone0 has 4 trip_points:
- trip_point_0_temp: shutdown temperature, set to 120 degrees by default
- trip_point_1_temp: used to control the fan speed. The default is 43 degrees, and the fan level range is 2~5, meaning that above 43 degrees, the fan will change from the off state to level 2, and can be raised up to level 5.
- trip_point_2_temp: used to control the fan speed. The default is 65 degrees, and the fan level range is 6~10, meaning that above 65 degrees, the fan will be adjusted to level 6, and can be raised up to level 10.
- trip_point_3_temp: used to control the CPU Acore frequency. The default is 95 degrees, meaning that above 95 degrees, the CPU Acore will scale down its frequency.
You can check the corresponding temperature settings through sysfs
```shell
root@ubuntu:~# cat /sys/devices/virtual/thermal/thermal_zone0/trip_point_0_temp
120000
```
If you want to adjust the corresponding temperature, e.g., start CPU frequency scaling at 85 degrees, you can use the following command:
```shell
echo 85000 > /sys/devices/virtual/thermal/thermal_zone0/trip_point_3_temp
```

##### thermal_zone1/2/3 Overview
thermal_zone1/2/3 each have 1 trip_point, which all represents the shutdown temperature. The default is 120 degrees.

thermal_zone4 has two trip_points, where
- trip_point_0_temp is the shutdown temperature, 120 degrees by default.
- trip_point_1_temp is the BPU frequency scaling temperature, 95 degrees by default.

For example, if you want the BPU to start frequency scaling when the junction temperature reaches 85 degrees Celsius:
```shell
echo 85000 > /sys/devices/virtual/thermal/thermal_zone4/trip_point_1_temp
```

If you want to adjust the shutdown temperature to 105 degrees Celsius, you can achieve this by modifying the trip_point_0_temp of all thermal zones
```shell
echo 105000 > /sys/devices/virtual/thermal/thermal_zone0/trip_point_0_temp
echo 105000 > /sys/devices/virtual/thermal/thermal_zone1/trip_point_0_temp
echo 105000 > /sys/devices/virtual/thermal/thermal_zone2/trip_point_0_temp
echo 105000 > /sys/devices/virtual/thermal/thermal_zone3/trip_point_0_temp
echo 105000 > /sys/devices/virtual/thermal/thermal_zone4/trip_point_0_temp
```

:::info
The above settings are only effective for the current boot. After <ins>reboot</ins>, they need to be set **again**.
:::

#### Cooling Devices
The RDK S100 has four cooling devices in total:

- cooling_device0: cpu cluster 0, controls temperature by adjusting frequency
- cooling_device1: cpu cluster 1, controls temperature by adjusting frequency
- cooling_device2: emc2305 fan, controls temperature by adjusting the fan speed level. The levels range from 0~10, where 0 means off and 10 means full fan speed.
- cooling_device3: bpu, controls temperature by adjusting frequency

Among them, the cooling devices CPU and fan are associated with thermal_zone0, and the cooling device BPU is associated with thermal_zone4. thermal_zone1/2/3 have no cooling device bound.

The current default policy is `step_wise`.

##### Fan Control
The emc2305 fan controller on the RDK S100 development board allows you to get basic device information and control the speed through device nodes:
1. Get cooling device information:
    ```shell
    root@ubuntu:~# cat /sys/class/thermal/cooling_device2/type
    emc2305_fan
    ```
2. Get the configurable fan levels:
    ```shell
    root@ubuntu:~# cat /sys/class/thermal/cooling_device2/max_state
    10
    ```
3. Get the current fan level
   ```shell
   root@ubuntu:~# cat /sys/class/thermal/cooling_device2/cur_state
   5
   ```
4. Set the policy of thermal_zone0 to `user_space`:
    ```
    echo user_space > /sys/class/thermal/thermal_zone0/policy
    ```
5. Set the current fan level to 10:
   ```shell
   root@ubuntu:~# echo 10 > /sys/class/thermal/cooling_device2/cur_state
   ```

:::info
**Note**: When the policy of thermal_zone0 is `step_wise`, the fan level configured by the user will be automatically adjusted by the system based on the current temperature. If the customer needs to fix the fan at a specific level, please refer to the [Thermal Zone Overview](#thermal-zone-overview) section and change the policy of thermal_zone0 to `user_space`
:::

### CPU Frequency Management

The Linux kernel has a built-in cpufreq subsystem for controlling the CPU frequency and frequency control policies.

Enter the directory `/sys/devices/system/cpu/cpufreq/policy0` and run `ls`. You will see the following files in the directory:

```shell
affected_cpus						# The CPU cores currently affected by the control (CPUs in the offline state are not shown)
cpuinfo_cur_freq					# Current CPU frequency (unit: KHz)
cpuinfo_max_freq					# The highest frequency available to the CPU under the current scaling policy (unit: KHz)
cpuinfo_min_freq					# The lowest frequency available to the CPU under the current scaling policy (unit: KHz)
cpuinfo_transition_latency			# The time required for the processor to switch frequencies (unit: ns)
related_cpus						# Which CPU cores are affected by this control policy (includes all CPUs, online + offline)
scaling_available_frequencies		# The list of main frequencies supported by the CPU (unit: KHz)
scaling_available_governors			# All governor (frequency scaling) types supported by the current kernel
scaling_cur_freq					# Holds the current CPU frequency cached by the cpufreq module, without checking the CPU hardware registers.
scaling_driver						# The frequency scaling driver currently in use
scaling_governor					# The governor (frequency scaling) policy
scaling_max_freq					# The highest frequency available to the CPU under the current scaling policy (read from the cpufreq module cache)
scaling_min_freq					# The lowest frequency available to the CPU under the current scaling policy (read from the cpufreq module cache)
scaling_setspeed					# Only usable after switching the governor to userspace; echoing a value to this file will switch the frequency
```

The currently supported frequencies include
```shell
cat /sys/devices/system/cpu/cpufreq/policy0/scaling_available_frequencies
1500000 2000000
```

Note: The supported frequency points may differ on different types of chips.
The Linux kernel used by the RDK S100 system supports the following types of frequency scaling policies:

- performance: runs at the highest frequency, i.e., the highest frequency supported by the hardware (highest performance).
- ondemand: adjusts the frequency according to the load
- userspace: uses the frequency set by the user
- powersave: runs at the lowest frequency
- schedutil: adjusts the frequency according to the load; it is used in combination with the CPU scheduler
- conservative: similar to Ondemand, but the frequency adjustment is smoother, without the phenomenon of suddenly adjusting to the maximum value and then suddenly adjusting to the minimum value

Users can control the CPU frequency scaling policy through the corresponding settings under the control directory `/sys/devices/system/cpu/cpu0/cpufreq/`.

For example, to run the CPU in performance mode:

```shell
echo performance >/sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
```

Or control the CPU to run at a fixed frequency (1.5GHz):

```shell
echo userspace >/sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
echo 1500000 >/sys/devices/system/cpu/cpufreq/policy0/scaling_setspeed
```

You can use the `sudo hrut_somstatus` command to check the current chip operating frequency, temperature, and other status.

## RDK S600
### Temperature Sensors
The RDK S600 chip has 19 temperature sensors, used to display the temperatures of the BPU/CPU/DDR. The BPU has 8 temperature sensors, the CPU has 7 temperature sensors, and the DDR has 4 temperature sensors.

Under /sys/class/hwmon/, the hwmon1 directory contains the relevant parameters of the temperature sensors:
- temp1_input through temp7_input are the CPU temperature sensors, and the corresponding labels are CMN0-TS[0-6]
- temp8_input through temp11_input are the DDR temperature sensors, and the corresponding labels are DDR[0-3]-TS0
- temp12_input through temp19_input are the BPU temperature sensors, and the corresponding labels are BPU[0-3]-TS0[0-1]

The temperature precision is one thousandth of a degree Celsius, and the range is -40~125 degrees Celsius.

```
root@ubuntu:~# cat /sys/class/hwmon/hwmon1/temp1_label
CMN0-TS0
root@ubuntu:~# cat /sys/class/hwmon/hwmon1/temp1_input
45129
```
The above is an example of the first CPU temperature sensor, named 'CMN0-TS0', with a temperature of 45.129 degrees Celsius.

##### CPU thermal_zone Overview

The CPU thermal_zones include thermal_zone0 through thermal_zone6.

thermal_zone2 has 5 trip_points:
- trip_point_0_temp: used to control the fan speed. The default is 45 degrees, and the fan level range is 2~5, meaning that above 45 degrees, the fan will change from the off state to level 2, and can be raised up to level 5.
- trip_point_1_temp: used to control the fan speed. The default is 65 degrees, and the fan level range is 6~10, meaning that above 65 degrees, the fan will be adjusted to level 6, and can be raised up to level 10 speed.
- trip_point_2_temp: used to control the CPU Acore frequency. The default is 95 degrees, meaning that above 95 degrees, the CPU Acore will scale down its frequency.
- trip_point_3_temp: hot temperature, set to 110 degrees by default, meaning that above 110 degrees, the system issues a hot warning.
- trip_point_4_temp: shutdown temperature, set to 115 degrees by default, meaning that above 115 degrees, the system will shut down.

You can check the corresponding temperature settings through sysfs
```shell
root@ubuntu:~# cat /sys/class/thermal/thermal_zone2/trip_point_0_temp
45000
```
If you want to adjust the corresponding temperature, e.g., start CPU frequency scaling at 85 degrees, you can use the following command:
```shell
echo 85000 > /sys/class/thermal/thermal_zone2/trip_point_2_temp
```

The other thermal_zones each have 1 trip_point, which all represents the shutdown temperature. The default is 115 degrees.

##### DDR thermal_zone Overview

The DDR thermal_zones include thermal_zone7 through thermal_zone10.

Each thermal_zone has 2 trip_points:
- trip_point_0_temp: hot temperature, set to 110 degrees by default, meaning that above 110 degrees, the system issues a hot warning.
- trip_point_1_temp: shutdown temperature, set to 115 degrees by default, meaning that above 115 degrees, the system will shut down.

##### BPU thermal_zone Overview

The BPU thermal_zones include thermal_zone11 through thermal_zone18.

thermal_zone16 has 5 trip_points, where
- trip_point_0_temp: used to control the fan speed. The default is 45 degrees, and the fan level range is 2~5, meaning that above 45 degrees, the fan will change from the off state to level 2, and can be raised up to level 5.
- trip_point_1_temp: used to control the fan speed. The default is 65 degrees, and the fan level range is 6~10, meaning that above 65 degrees, the fan will be adjusted to level 6, and can be raised up to level 10 speed.
- trip_point_2_temp: used to control the BPU frequency. The default is 95 degrees, meaning that above 95 degrees, the BPU will scale down its frequency.
- trip_point_3_temp: hot temperature, set to 110 degrees by default, meaning that above 110 degrees, the system issues a hot warning.
- trip_point_4_temp: shutdown temperature, set to 115 degrees by default, meaning that above 115 degrees, the system will shut down.

For example, if you want the BPU to start frequency scaling when the junction temperature reaches 85 degrees Celsius:

The other thermal_zones each have 1 trip_point, which all represents the shutdown temperature. The default is 115 degrees.

#### Cooling Devices
The RDK S600 has 11 cooling devices in total:

- cooling_device0~4: cpufreq, corresponding to cpufreq-cpu0/2/6/10/14, controlling temperature by adjusting the CPU frequency;
- cooling_device5~6: emc2305 fan, controlling temperature by adjusting the fan speed level. The levels range from 0~10, where 0 means off and 10 means full fan speed;
- cooling_device7~10: devfreq, corresponding to 28108000/29108000/2a108000/2b108000.bpu, controlling temperature by adjusting the BPU frequency.

The current default policy is `step_wise`.

##### Fan Control
The emc2305 fan controller on the RDK S600 development board allows you to get basic device information and control the speed through device nodes:
1. Get cooling device information:
    ```shell
    root@ubuntu:~# cat /sys/class/thermal/cooling_device5/type
    emc2305_fan
    ```
2. Get the configurable fan levels:
    ```shell

    ```

   ```shell
   root@ubuntu:~# cat /sys/class/thermal/cooling_device5/cur_state
   5
   ```
4. Set the policy of thermal_zone2 to `user_space`:
    ```
    # thermal_zone2 and thermal_zone16 will control the fan
    echo user_space > /sys/class/thermal/thermal_zone2/policy
    echo user_space > /sys/class/thermal/thermal_zone16/policy
    ```
5. Set the current fan level to 10:
   ```shell
   root@ubuntu:~# echo 10 > /sys/class/thermal/cooling_device5/cur_state
   ```

:::info
**Note**: When the policy of thermal_zone2 or thermal_zone16 is `step_wise`, the fan level configured by the user will be automatically adjusted by the system based on the current temperature. If the customer needs to fix the fan at a specific level, please refer to the [Thermal Zone Overview](#thermal-zone-overview) section and change the policy of thermal_zone2 and thermal_zone16 to `user_space`
:::
