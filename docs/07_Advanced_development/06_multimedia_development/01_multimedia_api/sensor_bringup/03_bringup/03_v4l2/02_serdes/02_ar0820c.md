# AR0820C Sensor Bring-Up

- 本文以 **AR0820C + MAX96712** GMSL yuv sensor 为例，说明 V4L2 模式下 GMSL/SerDes sensor 的适配流程。
- 流程包括驱动编写、数据通路与 sensor 配置、板端加载与取流验证。
- 通用 v4l2 subdev 框架见 [V4L2 mipi sensor 驱动编写说明](../01_mipi/01_sensor_driver.md)，GMSL SerDes 接口（serdes_ops / SERDES_OP）见 [V4L2 GMSL SERDES camera 驱动编写说明](./01_gmsl_serdes.md)，总览见 [V4L2 Camera 调试总览](../00_overview.md)。

:::note
本文以 RDK S100 开发板 + AR0820C（SG8S-AR0820C-5300-G2A）模组为例进行讲解，RDK S600 基本一致，其他硬件平台或 camera 模组以实际情况为准。
:::

**源码位置**

- sensor 驱动：`source/kernel/drivers/media/i2c/ar0820.c`
- serdes 框架头：`source/kernel/include/media/i2c/serdes_core.h`
- 用户态 sensor 库：`source/hobot-camera/`（`libar0820.so` / `libar0820std.so`）

## 1. dts 配置

1. AR0820C 经 MAX9295 加串器与 MAX96712 解串器接入 SoC，sensor dts 通过 `d-robotics,serdes-ser-device` 与 `d-robotics,serdes-dser-device` 两个 phandle 指向加串/解串节点。
2. 多路 GMSL sensor 经同一解串器汇聚，以 MIPI virtual channel（0~3）区分，共享一路 4-lane MIPI CSI；典型配置 4 路 AR0820C（i2c 地址 0x11~0x14）分别接解串 port A~D，对应 VC 0~3。
3. 接入非默认配置时以 dtbo overlay 覆盖，dtbo 编写见 [Sensor dtbo 文件编写配置说明](./01_gmsl_serdes.md#sensor-dtbo-文件编写配置说明)。

单路 AR0820C dts 节点示例：

```dts
ar0820@11 {
	compatible = "d-robotics,ar0820";
	reg = <0x11>;            // host 总线上的 i2c 地址（映射后）
	addr = <0x10>;           // sensor 物理 i2c 地址
	width = <1920>;
	height = <1080>;
	data_type = <0x1e>;      // SERDES_MIPI_DT_YUV422_8
	lane_num = <4>;
	mfp-reset = <0>;         // reset 接到加串器 mfp
	mfp-trigger = <7>;       // trigger pin 接到加串器 mfp
	d-robotics,serdes-ser-device = <&ser_a>;   // 指向加串节点
	d-robotics,serdes-dser-device = <&dser>;    // 指向解串节点
	status = "okay";

	port {
		cam_0_to_mipi_csi4: endpoint {    // 接入 mipi rx4
			remote-endpoint = <&mipi_csi4_from_cam_0>;
			virtual-channel = <0>;    // 解串器送给 SoC 的 MIPI VC
		};
	};
};
```

dts 关键属性：

| 属性 | 用途 | 必填 |
| --- | --- | --- |
| `reg` | host 总线 i2c 地址（映射后） | 是 |
| `addr` | sensor 物理 i2c 地址 | 是 |
| `width` / `height` | 分辨率（默认 1920 / 1080） | 否 |
| `data_type` | MIPI 数据类型（默认 0x1e YUV422-8） | 否 |
| `lane_num` | MIPI lane 数（默认 4） | 否 |
| `mfp-reset` / `mfp-trigger` | 接到加串器的 reset / trigger mfp 管脚 | 否 |
| `d-robotics,serdes-ser-device` | phandle 指向加串节点 | 是 |
| `d-robotics,serdes-dser-device` | phandle 指向解串节点 | 是 |

## 2. 驱动

ar0820 是标准 v4l2 subdev 驱动，但与 MIPI 直连 sensor（如 imx219）不同：它是一个**薄 serdes 传输层**——不含 AR0820 寄存器表、mode 表、曝光/gain 控制或开关流寄存器序列，sensor 侧配置全部由用户态 `libar0820.so` 经 serdes 完成。v4l2 subdev 框架见 [V4L2 mipi sensor 驱动编写说明](../01_mipi/01_sensor_driver.md)，serdes 接口见 [V4L2 GMSL SERDES camera 驱动编写说明](./01_gmsl_serdes.md)。

### 2.1 框架与注册入口

1. ar0820 私有结构体 `struct ar0820` 承载 v4l2 subdev、media pad、加串/解串设备句柄（`ser_dev` / `dser_dev`）、serdes context（`g_ctx`）及 dts 解析的分辨率/数据类型/mfp 等参数。
2. probe 函数 `ar0820_probe` 完成 subdev 初始化、dts 解析、serdes 链路建立与异步注册。
3. probe 调用时机为 i2c client 匹配 `compatible = "d-robotics,ar0820"` 后内核自动调用。

`struct ar0820` 定义：

```c
struct ar0820 {
	struct device *dev;
	struct i2c_client *client;
	struct v4l2_subdev sd;
	struct serdes_device *ser_dev;      // 加串器（max9295）
	struct serdes_device *dser_dev;     // 解串器（max96712）
	struct serdes_ctx g_ctx;            // serdes context，传给加/解串
	struct media_pad pad;
	struct v4l2_mbus_framefmt fmt;
	struct v4l2_ctrl_handler ctrl_handler;
	struct mutex serdes_mutex;
	struct mutex mutex;
	int width, height, data_type;
	int mfp_reset, mfp_trigger;
	u32 lane_num;
};
```

`ar0820_probe` 关键步骤：

```c
static int ar0820_probe(struct i2c_client *client)
{
	priv = devm_kzalloc(&client->dev, sizeof(*priv), GFP_KERNEL);          // 1. 分配
	v4l2_i2c_subdev_init(&priv->sd, client, &ar0820_subdev_ops);           // 2. subdev 绑定 i2c
	ar0820_initialize_controls(priv);   // 3. ctrl handler init（当前为 TODO，无 ctrl）
	ar0820_power_on(priv);              // 4. 上电（当前为 no-op）
	ar0820_init(priv);                  // 5. parse_dt + 加/解串 set_ctx
	ar0820_serdes_setup(priv);          // 6. 建立 serdes 链路

	priv->sd.internal_ops = &ar0820_internal_ops;
	priv->sd.flags |= V4L2_SUBDEV_FL_HAS_DEVNODE | V4L2_SUBDEV_FL_HAS_EVENTS;
	priv->pad.flags = MEDIA_PAD_FL_SOURCE;
	priv->sd.entity.function = MEDIA_ENT_F_CAM_SENSOR;
	media_entity_pads_init(&priv->sd.entity, 1, &priv->pad);               // 7. media pad
	v4l2_async_register_subdev_sensor(&priv->sd);                         // 8. 异步注册
	return 0;
}
```

其中 `ar0820_serdes_setup` 通过 `SERDES_OP` 完成完整 serdes 链路建立：

```c
SERDES_OP(priv->dser_dev, init,                priv->dser_dev);                    // 解串器初始化
SERDES_OP(priv->dser_dev, setup_link,          priv->dser_dev, sen_dev);          // 建立 link
SERDES_OP(priv->dser_dev, remote_contrl_get,   priv->dser_dev, sen_dev);          // 地址重映射前加锁
SERDES_OP(priv->ser_dev,  map_addr,            priv->ser_dev);                    // 重映射加串/sensor i2c 地址
SERDES_OP(priv->dser_dev, remote_contrl_put,   priv->dser_dev);                   // 解锁
SERDES_OP(priv->ser_dev,  init,                priv->ser_dev);                    // 加串器初始化
SERDES_OP(priv->ser_dev,  set_pipe,            priv->ser_dev, sen_dev);           // 配置加串 video pipe
SERDES_OP(priv->dser_dev, set_pipe,            priv->dser_dev, sen_dev);          // 配置解串 video pipe
SERDES_OP(priv->ser_dev,  clear_mfp,           priv->ser_dev, priv->mfp_reset);   // reset 拉低
SERDES_OP(priv->ser_dev,  enable_mfp,          priv->ser_dev, priv->mfp_reset);   // reset 拉高
SERDES_OP(priv->ser_dev,  clear_mfp,           priv->ser_dev, priv->mfp_trigger); // trigger 初始化
```

### 2.2 实现的接口

1. ar0820 注册 `v4l2_subdev_ops`（video + pad）与 `v4l2_subdev_internal_ops`，无 core ops。
2. video ops 的 `s_stream` 控制解串器触发使能（非 sensor 寄存器开关流）。
3. pad ops 提供格式协商与分辨率枚举，格式固定为 YUV422-8。
4. internal ops 的 `open` / `close` 管理子设备生命周期，`close` 时关流。
5. 驱动不暴露任何 v4l2 ctrl（exposure / gain 等）——`ctrl_handler` 预留 9 个槽位但内容为 TODO，因 AR0820 自带 ISP 输出 YUV，板端不做 AE。

注册的 ops：

```c
static const struct v4l2_subdev_video_ops ar0820_video_ops = {
	.s_stream = ar0820_s_stream,
};
static const struct v4l2_subdev_pad_ops ar0820_subdev_pad_ops = {
	.enum_mbus_code  = ar0820_enum_mbus_code,
	.get_fmt         = ar0820_get_fmt,
	.set_fmt         = ar0820_set_fmt,
	.enum_frame_size = ar0820_enum_frame_size,
};
static const struct v4l2_subdev_ops ar0820_subdev_ops = {
	.video = &ar0820_video_ops,
	.pad   = &ar0820_subdev_pad_ops,
};
static const struct v4l2_subdev_internal_ops ar0820_internal_ops = {
	.open  = ar0820_open,
	.close = ar0820_close,
};
```

接口说明：

| ops | 接口 | 功能 |
| --- | --- | --- |
| video | `s_stream` | 使能/关闭解串器 trigger 输出 |
| pad | `enum_mbus_code` / `get_fmt` / `set_fmt` | 格式固定 `MEDIA_BUS_FMT_YUYV8_1X16`（YUV422-8） |
| pad | `enum_frame_size` | 仅支持 1920x1080 |
| internal | `open` | 子设备打开，应用默认格式 |
| internal | `close` | 子设备关闭，调用 `set_stream(0)` 关流 |

流控制（`ar0820_set_fmt` / `ar0820_s_stream` / `ar0820_close`）：

1. `ar0820_set_fmt`（pipeline open 时调用）配置加串 mfp（trigger RX）、解串 mfp（TX）、`trigger_cfg(33333000ns, 10000ns)`（约 30fps），并调用解串 `set_stream(1)` 开始出流。
2. `ar0820_s_stream` 仅调用解串 `trigger_enable(enable)`，开关 trigger。
3. `ar0820_close` 调用解串 `set_stream(0)` 关流。

```c
// set_fmt 中的流控配置
SERDES_OP(priv->ser_dev,  mfp_cfg,     priv->ser_dev,  sen_dev, priv->mfp_trigger, GPIO_RX_GMSL, 1);
SERDES_OP(priv->dser_dev, mfp_cfg,     priv->dser_dev, sen_dev, 0, GPIO_TX_GMSL, 1);
SERDES_OP(priv->dser_dev, trigger_cfg, priv->dser_dev, sen_dev, 33333000, 10000);   // 30fps
SERDES_OP(priv->dser_dev, set_stream,  priv->dser_dev, sen_dev, 1);

// s_stream 仅开关 trigger
SERDES_OP(priv->dser_dev, trigger_enable, priv->dser_dev, sen_dev, enable);

// close 关流
SERDES_OP(priv->dser_dev, set_stream, priv->dser_dev, sen_dev, 0);
```

## 3. 数据通路与 sensor 配置

1. AR0820 是 YUV422 sensor，自带 ISP，输出已处理好的 YUV422-8 帧（MIPI DT 0x1E）。
2. 板端 SoC ISP 对其 bypass——不经 VIN→ISP→PYM 的 RAW 处理链路，YUV 直接到 DDR。
3. 因此驱动不暴露 exposure/gain ctrl，也无 gain_lut AE 库，区别于 RAW sensor（如 imx219 的 [用户态 AE 库](../01_mipi/02_imx219.md)）。
4. sensor 侧配置（AE/AWB/ISP/stream-on 寄存器）由用户态 `libar0820.so` / `libar0820std.so` 经 serdes 的 `write_sensor` / `read_sensor` 远程读写 AR0820 寄存器完成，内核驱动不参与。

:::note
YUV sensor 板端 ISP bypass，AE/AWB 在 sensor 端 ISP 完成，板端无 AE 调试链路；RAW sensor 才需 [用户态 AE 库](../00_overview.md#ae库--驱动--isp_service-关系)。
:::

## 4. app 测试

### 4.1 卸载 HBN 驱动、加载 V4L2 驱动

1. HBN 与 V4L2 两套 camsys 驱动互斥，切换到 V4L2 模式前必须先卸载 HBN 驱动。
2. 再按依赖顺序加载 V4L2 相关 ko：videobuf2 系列 → serdes_core → max96712/max9295a → ar0820 → camsys v4l2 模块（v4l_mipicsi / v4l2_cim / hobot_isp_v4l2 / pym_v4l_drv / gdc_v4l_drv / hobot_ynr_v4l2）→ vid_v4l2。
3. 最后启动 `isp_service`。

```bash
# 卸载 hbn 驱动
rmmod hobot_isp
rmmod hobot_cim
rmmod hobot_mipidbg
rmmod hobot_mipicsi
rmmod hobot_pym_jplus
rmmod hobot_gdc
rmmod hobot_ynr

# 加载 v4l2 驱动
echo ion > /sys/module/hobot_camsys_adapter/parameters/mops   # ion 或 dma 可选
modprobe videobuf2-common
modprobe videobuf2-v4l2
modprobe videobuf2-memops
modprobe videobuf2-common
modprobe videobuf2-dma-contig
modprobe videobuf2-v4l2
modprobe v4l2-mem2mem
modprobe serdes_core
modprobe max96712
modprobe max9295a
modprobe ar0820
modprobe v4l_mipicsi
modprobe v4l2_cim
modprobe hobot_isp_v4l2
modprobe pym_v4l_drv
modprobe gdc_v4l_drv
modprobe hobot_ynr_v4l2
modprobe vid_v4l2 scene=0
nohup isp_service &
```

确认加载成功：

1. `lsmod | grep ar0820` 有 `ar0820` 条目即驱动加载成功。
2. `ls /dev/video*` 确认 video 节点已生成；AR0820 接入的 RX 与 `scene` 决定节点号，本例接 RX4、`scene=0` 对应 `/dev/video2`（`video0`/`video1` 为 RX0/RX1，未使用）。
3. `dmesg | grep ar0820` 查看 probe 日志，确认 `width / height / data_type / mfp_reset / mfp_trigger` 与 dts 一致。

```bash
lsmod | grep ar0820
ls /dev/video*
dmesg | grep ar0820
```

### 4.2 media 拓扑查看

1. `media-ctl -p` 打印 media controller 拓扑。
2. 确认 ar0820 subdev → max96712 解串 → mipi_csi → cim → DDR 的链接完整。
3. 多路接入时确认各路 VC（0~3）与解串 pipe 对应正确。
4. 用 `v4l2-ctl --get-fmt-video` 与 `--list-formats` 确认 video 节点当前格式与支持的格式。

```bash
media-ctl -p
v4l2-ctl -d /dev/video2 --get-fmt-video
v4l2-ctl -d 0 --list-formats
```

### 4.3 取流

1. AR0820 输出 YUV422，板端 ISP bypass，走 `vid_v4l2 scene=0` 从 CIM 直接接收（`scene=0`=CIM、`scene=4`=ISP；YUV bypass 用 `scene=0`，不经 ISP）。
2. AR0820 接 RX4、`scene=0` 对应 `/dev/video2`（以 `ls /dev/video*` 与 `media-ctl -p` 为准）。
3. 用 `v4l2-ctl` 设置格式抓帧，或 `ffplay` 直接预览。

**取 YUV**（`scene=0`，CIM 直收，`/dev/video2`）：

```bash
modprobe vid_v4l2 scene=0
v4l2-ctl -d /dev/video2 --set-fmt-video=width=1920,height=1080,pixelformat=NV12,field=none \
	--stream-mmap --stream-to=frame.yuv --stream-count=1
```

直接预览：

```bash
ffplay -f v4l2 -video_size 1920x1080 -pixel_format nv12 -i /dev/video2
```

## 5. 程序验证

1. YUV sensor 无 AE 手动验证链路（板端 ISP bypass），验证以**出图与帧率**为主。
2. 用 `v4l2-ctl --get-fmt-video` / `--list-formats` 确认 video 节点格式与分辨率。
3. 抓帧后检查图像内容与帧率是否符合 1920x1080 @ 30fps。
4. 多路接入时，逐路抓帧确认各 VC 视频节点独立出图。

```bash
v4l2-ctl -d /dev/video2 --get-fmt-video
v4l2-ctl -d 0 --list-formats
v4l2-ctl -d /dev/video2 --set-fmt-video=width=1920,height=1080,pixelformat=NV12,field=none \
	--stream-mmap --stream-count=1 --stream-to=frame.yuv
```

:::note
若需验证 sensor 端 AE/AWB 效果，需通过 `libar0820.so`（经 serdes 远程读写 AR0820 寄存器）调试，不在 v4l2-ctl 链路内。
:::
