# imx219 Sensor Bring-Up

- 本文以 **imx219** 为例，说明 V4L2 模式下 MIPI 直连 sensor 的适配流程。
- 流程包括驱动编写、用户态 AE 库、板端加载与取流验证。
- 通用 v4l2 subdev 框架与 AE 库/驱动/isp_service 关系请先阅读 [V4L2 Camera 调试总览](../00_overview.md)，GMSL/SerDes 接入见 [V4L2 GMSL SERDES camera 驱动编写说明](../02_serdes/01_gmsl_serdes.md)。

**源码位置**

- sensor 驱动：`source/kernel/drivers/media/i2c/imx219.c`
- 用户态 AE 库：`source/hobot-camera/drivers/sensor/imx219_v4l2/`（生成 `libimx219_v4l2.so.1.0.0`）

:::note
本文以 RDK S100 开发板 + imx219 模组为例进行讲解，RDK S600 基本一致，其他硬件平台或 camera 模组以实际情况为准。
:::

---

## 1. dts 配置

1. imx219 作为 MIPI 直连 sensor，dts 在 i2c 节点下描述 sensor 及 endpoint，对接到 `mipi_host`。
2. imx219 硬件规格固定为 2 lane、24MHz xclk、456MHz link freq，dts 中需与之一致。
3. 接入非默认 sensor 时，以 dtbo overlay 方式覆盖默认 dts，dtbo 编写见 [Sensor dtbo 文件编写配置说明](../02_serdes/01_gmsl_serdes.md#sensor-dtbo-文件编写配置说明)。
4. 默认 dts 与 dtbo overlay 两种接入方式的差异见 [V4L2 Camera 调试总览 - V4L2 接入方式](../00_overview.md#v4l2-接入方式)。

imx219 默认 dts 节点示例：

```dts
&i2c1 {
	status = "okay";

	imx219@10 {
		status = "okay";
		compatible = "sony,imx219";
		reg = <0x10>;           // sensor i2c 地址
		clocks = <&clk 0>;       // 24MHz xclk
		/* 供电 / regulator / gpio-reset 按板级配置 */
		port {
			cam_to_mipi_csi0: endpoint {
				remote-endpoint = <&rdk_s100_mipi_csi0_from_cam>;
				clock-lanes = <0>;
				data-lanes = <1 2>;    // imx219 固定 2 lane
				link-frequencies = /bits/ 64 <456000000>;  // 456MHz
			};
		};
	};
};
```

## 2. 驱动

imx219 是标准 v4l2 subdev 驱动（MIPI 直连，不经 SerDes）。v4l2 subdev 框架概要见 [V4L2 Camera 调试总览](../00_overview.md#v4l2-subdev-驱动框架概要)，本节按 imx219 实例说明需实现的内容。

### 2.1 框架与注册入口

1. imx219 私有结构体 `struct imx219` 承载 v4l2 subdev 句柄、media pad、i2c client、供电/时钟/reset、v4l2 ctrl handler 与当前模式等。
2. probe 函数 `imx219_probe` 完成 subdev 初始化、硬件校验、chip id 识别、ctrl 初始化与异步注册。
3. probe 调用时机为 i2c client 匹配 `compatible` 后内核自动调用。

`struct imx219` 定义：

```c
struct imx219 {
	struct v4l2_subdev sd;
	struct media_pad pad;
	struct v4l2_mbus_framefmt fmt;
	struct clk *xclk;                 // 24MHz 系统时钟
	u32 xclk_freq;
	struct gpio_desc *reset_gpio;
	struct regulator_bulk_data supplies[IMX219_NUM_SUPPLIES];  // VANA/VDIG/VDDL
	struct v4l2_ctrl_handler ctrl_handler;
	struct v4l2_ctrl *pixel_rate, *link_freq;
	struct v4l2_ctrl *exposure, *vflip, *hflip, *vblank, *hblank;
	const struct imx219_mode *mode;   // 当前模式
	struct mutex mutex;
	bool streaming;
};
```

`imx219_probe` 关键步骤：

```c
static int imx219_probe(struct i2c_client *client)
{
	imx219 = devm_kzalloc(&client->dev, sizeof(*imx219), GFP_KERNEL);   // 1. 分配
	v4l2_i2c_subdev_init(&imx219->sd, client, &imx219_subdev_ops);     // 2. subdev 绑定 i2c

	imx219_check_hwcfg(dev);              // 3. 校验 dts endpoint（2 lane + 456MHz link freq）
	imx219->xclk = devm_clk_get(dev, NULL);   // 4. 取 24MHz xclk
	imx219_get_regulators(imx219);        // 5. 取 VANA/VDIG/VDDL 供电
	imx219->reset_gpio = devm_gpiod_get_optional(dev, "reset", GPIOD_OUT_HIGH);

	imx219_power_on(dev);
	imx219_identify_module(imx219);       // 6. 读 CHIP_ID 寄存器，期望 0x0219

	imx219->mode = &supported_modes[0];   // 7. 默认模式（最高分辨率）
	imx219_init_controls(imx219);         // 8. 初始化 v4l2_ctrl（exposure/gain/flip...）

	imx219->sd.internal_ops = &imx219_internal_ops;
	imx219->sd.flags |= V4L2_SUBDEV_FL_HAS_DEVNODE | V4L2_SUBDEV_FL_HAS_EVENTS;
	imx219->sd.entity.function = MEDIA_ENT_F_CAM_SENSOR;
	imx219->pad.flags = MEDIA_PAD_FL_SOURCE;

	media_entity_pads_init(&imx219->sd.entity, 1, &imx219->pad);   // 9. media pad（1 个 source pad）
	v4l2_async_register_subdev_sensor(&imx219->sd);                // 10. 异步注册到 v4l2 框架
	pm_runtime_enable(dev);
	return 0;
}
```

其中：

1. `v4l2_i2c_subdev_init` 将 subdev 与 i2c client 绑定，后续 v4l2 框架通过 subdev ops 控制 sensor。
2. `imx219_check_hwcfg` 解析 dts endpoint，强制要求 2 lane 与 456MHz link freq，与 imx219 硬件规格一致。
3. `imx219_identify_module` 读 CHIP_ID 寄存器（0x0000），期望值 0x0219，用于校验 sensor 在线与型号正确。
4. `media_entity_pads_init` 声明 1 个 source pad，使 media controller 能将 sensor 与后级 mipi_csi/cim/isp 建立链接。
5. `v4l2_async_register_subdev_sensor` 异步注册，等待后级 pipeline 就绪后完成绑定。

### 2.2 实现的接口

1. imx219 驱动需实现 `v4l2_subdev_ops`（含 core/video/pad）与 `v4l2_subdev_internal_ops`，由 V4L2 框架回调。
2. video ops 的 `s_stream` 必须实现，控制 sensor 开关流。
3. pad ops 的格式协商接口（`enum_mbus_code`/`get_fmt`/`set_fmt`/`enum_frame_size`）必须实现。
4. core ops 与 internal ops 按需实现，用于事件订阅与子设备生命周期管理。
5. AE 相关通过 v4l2 ctrl（`V4L2_CID_EXPOSURE`/`V4L2_CID_ANALOGUE_GAIN` 等）暴露，`s_ctrl` 回调将 ctrl 值写入 sensor 寄存器。

注册的 ops：

```c
static const struct v4l2_subdev_core_ops imx219_core_ops = {
	.subscribe_event = v4l2_ctrl_subdev_subscribe_event,
	.unsubscribe_event = v4l2_event_subdev_unsubscribe,
};
static const struct v4l2_subdev_video_ops imx219_video_ops = {
	.s_stream = imx219_set_stream,
};
static const struct v4l2_subdev_pad_ops imx219_pad_ops = {
	.enum_mbus_code = imx219_enum_mbus_code,
	.get_fmt = imx219_get_pad_format,
	.set_fmt = imx219_set_pad_format,
	.get_selection = imx219_get_selection,
	.enum_frame_size = imx219_enum_frame_size,
};
static const struct v4l2_subdev_ops imx219_subdev_ops = {
	.core = &imx219_core_ops,
	.video = &imx219_video_ops,
	.pad = &imx219_pad_ops,
};
static const struct v4l2_subdev_internal_ops imx219_internal_ops = {
	.open = imx219_open,
};
```

接口说明：

| ops | 接口 | 功能 |
| --- | --- | --- |
| video | `s_stream` | 开/关流：写 0x0100 = 0x01 出流 / 0x00 待机 |
| pad | `enum_mbus_code` / `get_fmt` / `set_fmt` | 格式协商（RAW10/RAW8，RGGB/GRBG/GBRG/BGGR） |
| pad | `get_selection` / `enum_frame_size` | 裁剪区与分辨率枚举 |
| core | `subscribe_event` / `unsubscribe_event` | v4l2 ctrl 事件订阅 |
| internal | `open` | 子设备打开回调 |
| ctrl | `s_ctrl`（`imx219_set_ctrl`） | exposure/gain/flip/vblank 寄存器下发 |

支持的 mode（`supported_modes[]`）：

| 分辨率 | 帧率 | 裁剪 | binning |
| --- | --- | --- | --- |
| 3264x2464 | 15fps | 全画幅 | 否 |
| 1920x1080 | 30fps | 居中裁剪 | 否 |
| 1640x1232 | 30fps | 全画幅 | 2x2 |
| 640x480 | 30fps | 裁剪 | 2x2 |

开/关流：

1. `imx219_start_streaming` 开流前依次下发 `imx219_common_regs`（公共配置）、当前 mode 的 `reg_list`（分辨率/裁剪）、raw 格式寄存器（raw8/raw10），并应用 v4l2 ctrl 配置。
2. 最后写 `IMX219_REG_MODE_SELECT`（0x0100）= 0x01 使 sensor 出流。
3. `imx219_stop_streaming` 写 0x0100 = 0x00 使 sensor 进入待机。

AE 控制寄存器（`imx219_set_ctrl` 写）：

| v4l2 ctrl | 寄存器 | 位宽 | 范围 |
| --- | --- | --- | --- |
| `V4L2_CID_ANALOGUE_GAIN` | 0x0157 | 8bit | 0 ~ 232 |
| `V4L2_CID_EXPOSURE` | 0x015a | 16bit | 4 ~ vts-4 |
| `V4L2_CID_DIGITAL_GAIN` | 0x0158 | 16bit | 0x0100 ~ 0x0fff |
| `V4L2_CID_VFLIP` / `HFLIP` | 0x0172 | - | 0/1 |
| `V4L2_CID_VBLANK` | 0x0160 | - | 4 ~ VTS_MAX |

## 3. 用户态 AE 库 imx219_v4l2

1. RAW sensor 对接 ISP，除驱动外还需一个 so 存放 gain lut 转换表，供 ISP AE 算法下发 gain 时查到对应 sensor 寄存器值。
2. AE 库与驱动、isp_service 的关系见 [AE库 / 驱动 / isp_service 关系](../00_overview.md#ae库--驱动--isp_service-关系)。
3. imx219 的 AE 库源码在 `source/hobot-camera/drivers/sensor/imx219_v4l2/imx219_camera_helper.c`，编译产物 `libimx219_v4l2.so.1.0.0`，运行时 isp_service 自动 dlopen 匹配。

### 3.1 gain_lut

1. again/dgain lut 为 uint32 数组，最多 256 项，每个成员为 gain 寄存器配置值。
2. 相邻成员对应的 dB 需连续，以匹配人眼对数感知与 ISP AE 步进。
3. 末尾固定 `0xffff` 作为结束标志。

```c
static uint32_t imx219_again_lut[] = {
	0x00,   // 0dB
	0x05,   // 约 0.2dB
	0x0B,   // 约 0.4dB
	0x0F,
	0x15,
	// ...
	0xE7,
	0xE8,   // 约 20.6dB，sensor again max
	0xffff, // end flag
};

static uint32_t imx219_dgain_lut[] = {
	0x0100,  // 0dB
	0x0106,  // 约 0.2dB
	0x010c,
	// ...
	0x0fd9,  // 约 24.0dB，sensor dgain max
	0xffff,  // end flag
};
```

index→reg callback 与获取接口：

1. `again_index_to_reg_function` / `dgain_index_to_reg_function` 接收 ISP 下发的 uint8 索引，越界则钳位到最后一项，返回对应寄存器值。
2. `get_index_to_reg_callbacks` 返回 callback 结构体，供 isp_service dlopen 后调用。

```c
typedef uint32_t (*AGainIndexToReg_t)(uint8_t);
typedef uint32_t (*DGainIndexToReg_t)(uint8_t);
typedef struct {
	AGainIndexToReg_t again_index_to_reg_callback;
	DGainIndexToReg_t dgain_index_to_reg_callback;
} Callbacks;

uint32_t again_index_to_reg_function(uint8_t isp_index) {
	if (isp_index >= sizeof(imx219_again_lut)/sizeof(uint32_t))
		isp_index = sizeof(imx219_again_lut)/sizeof(uint32_t) - 1;
	return imx219_again_lut[isp_index];
}
uint32_t dgain_index_to_reg_function(uint8_t isp_index) {
	if (isp_index >= sizeof(imx219_dgain_lut)/sizeof(uint32_t))
		isp_index = sizeof(imx219_dgain_lut)/sizeof(uint32_t) - 1;
	return imx219_dgain_lut[isp_index];
}
Callbacks cb = {again_index_to_reg_function, dgain_index_to_reg_function};
Callbacks *get_index_to_reg_callbacks() { return &cb; }
```

数据流：

1. isp_service 的 AE 算法输出 gain 索引。
2. 通过 `get_index_to_reg_callbacks` 拿到 callback，查 lut 得 sensor 寄存器值。
3. isp_service 通过 v4l2 ctrl（`analogue_gain`/`exposure`）下发到驱动。
4. 驱动 `imx219_set_ctrl` 将值写入 0x0157/0x015a 寄存器。

## 4. app 测试

### 4.1 卸载 HBN 驱动、加载 V4L2 驱动

1. HBN 与 V4L2 两套 camsys 驱动互斥，切换到 V4L2 模式前必须先卸载 HBN 驱动。
2. 再按依赖顺序加载 V4L2 相关 ko（videobuf2 系列 → serdes_core → sensor → camsys v4l2 模块）。
3. 最后启动 `isp_service`，由其承载 AE/AWB 算法并 dlopen sensor AE 库。

```bash
# 卸载 hbn 驱动
rmmod hobot_isp
rmmod hobot_cim
rmmod hobot_mipidbg
rmmod hobot_mipicsi
rmmod hobot_pym_jplus
rmmod hobot_gdc
rmmod hobot_ynr

# 加载 v4l2 驱动
echo ion > /sys/module/hobot_camsys_adapter/parameters/mops   # ion 或 dma 可选
modprobe videobuf2-common
modprobe videobuf2-v4l2
modprobe videobuf2-memops
modprobe videobuf2-dma-contig
modprobe v4l2-mem2mem
modprobe serdes_core
modprobe imx219
modprobe v4l_mipicsi
modprobe v4l2_cim
modprobe hobot_isp_v4l2
modprobe pym_v4l_drv
modprobe gdc_v4l_drv
modprobe hobot_ynr_v4l2
modprobe vid_v4l2 scene=0
nohup isp_service &
```

确认加载成功：

1. 执行 `lsmod | grep imx219`，有 `imx219` 条目即驱动加载成功。
2. 若无条目，检查 dmesg 中 i2c 通信、chip id 校验、供电是否正常。

```bash
lsmod | grep imx219
```

### 4.2 media 拓扑查看

1. 执行 `media-ctl -p` 打印 media controller 拓扑。
2. 确认 imx219 subdev → mipi_csi → cim → isp → pym/gdc/ynr 的链接关系完整。
3. 确认 sensor pad 的格式与帧率与配置的 mode 一致。

```bash
media-ctl -p
```

### 4.3 取流

1. V4L2 模式下通过 `vid_v4l2` 的 `scene` 参数选择数据通路：`scene=0` 仅 VIN 出 raw，`scene=4` 走 ISP 出 YUV。
2. 用 `v4l2-ctl` 设置输出格式并抓取指定帧数。
3. 也可用 `ffplay` 直接预览。

**取 RAW**（`scene=0`，仅 VIN 出 raw）：

```bash
modprobe vid_v4l2 scene=0
v4l2-ctl -d /dev/video0 --set-fmt-video=width=1920,height=1080,pixelformat=RG10 \
	--stream-mmap --stream-to=frame.raw --stream-count=1
```

**取 YUV**（`scene=4`，走 ISP 出 YUV）：

```bash
modprobe vid_v4l2 scene=4
v4l2-ctl -d /dev/video0 --set-fmt-video=width=1920,height=1080,pixelformat=NV12 \
	--stream-mmap --stream-count=1 --stream-to=./frame.nv12
```

直接预览：

```bash
ffplay -f v4l2 -video_size 1920x1080 -pixel_format nv12 -i /dev/video0
```

## 5. 程序验证 AE

1. 将 AE 切为手动，用 `v4l2-ctl` 设 exposure 与 analog gain，下发的是 sensor 寄存器值（非 ISP 索引）。
2. 用 `i2ctransfer` 读 imx219 寄存器，核对驱动是否正确写入。
3. 读回值应与设置值一致；若不一致，检查 `imx219_set_ctrl` 是否被调用及 ctrl 值是否在范围内。

```bash
# 设 exposure=256（0x100，写 0x015a 16bit）、analog gain=32（0x20，写 0x0157 8bit）
v4l2-ctl -d /dev/video0 --set-ctrl=exposure=256
v4l2-ctl -d /dev/video0 --set-ctrl=analogue_gain=32

# 读 imx219 寄存器核对（i2c1，sensor addr 0x10，16bit 寄存器地址）
i2ctransfer -y 1 w2@0x10 0x01 0x5a r2    # exposure 寄存器 0x015a，读 2 字节
i2ctransfer -y 1 w2@0x10 0x01 0x57 r1    # analog gain 寄存器 0x0157，读 1 字节
```

:::note
`v4l2-ctl --set-ctrl=analogue_gain` 下发的是 sensor 寄存器值（0~232，直接写 0x0157）；isp_service 的 AE 自动路径则是输出 gain 索引、经 `imx219_v4l2` 的 lut 查表得寄存器值再下发。手动验证用前者即可。
:::
